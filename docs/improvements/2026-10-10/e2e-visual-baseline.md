# 랜딩 페이지 시각 회귀 기준 갱신

2026-10-11. 커밋 `38c3098`의 [E2E 실행](https://github.com/Muneo-official/Muneo-FE/actions/runs/38066453734)에서 52개 중 51개가 통과하고 랜딩 페이지 전체 스크린샷 비교 1개가 실패했다.

## 원인과 수정

운영자·문의 이메일을 푸터에 추가하고 챗봇 버튼·소개 문구를 정리한 화면 변경이 기존 기준 이미지에 반영되지 않았다. 기존 크기는 1440×3661, 변경 후 크기는 1440×3704다.

CI의 `test-results` 아티팩트에서 기존 이미지·실제 이미지·차이 이미지를 직접 대조했다. 변경 영역은 소개 문구, 챗봇 버튼 제거, 운영 정보 추가와 그에 따른 푸터 배치다. 최초 실행과 재시도 2회의 실제 PNG 파일은 SHA-256이 모두 같았다.

- 수정 파일: `e2e/visual.spec.ts-snapshots/landing-full-chromium-linux.png`
- 이미지 출처: 위 실행의 `landing-full-actual.png` (Linux Chromium)
- 이미지 SHA-256: `afc65e0142dac145523a71f6ad4f582d3d08dded2146e9aecf481bf1e94c271d`
- 검토한 CI 이미지를 그대로 복사했다. 이미지 편집, 비교 허용치 변경, 테스트 제외는 하지 않았다.
- Linux에서 새로 실행하는 전체 E2E 결과로 최종 확인한다. 기존 실패 실행에서 통과한 51개와 수정 후 전체 통과 여부는 구분한다.

## 이후 화면을 변경할 때

1. 실패 실행의 `test-results` 아티팩트를 내려받는다.
2. `*-expected.png`, `*-actual.png`, `*-diff.png`를 변경 코드와 대조한다. 의도하지 않은 차이는 먼저 구현을 수정한다.
3. 의도한 변경만 확인되면 같은 Linux 환경의 실제 캡처로 기준 이미지를 갱신한다. 같은 환경에서 재생성하려면 `pnpm test:e2e:update e2e/visual.spec.ts`를 실행한다.
4. 변경된 이미지를 커밋하고 업데이트 옵션 없이 전체 E2E를 다시 실행해 통과 여부를 확인한다.

macOS에서 생성한 이미지를 Linux 기준 파일로 이름만 바꿔 넣지 않는다. 폰트·브라우저 렌더링 차이가 포함될 수 있다. 화면이 달라졌다는 이유만으로 `maxDiffPixelRatio`를 높이거나 테스트를 건너뛰지 않는다.
