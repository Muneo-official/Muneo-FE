이번 작업은 **프론트엔드 구현 + 개선 기획 + 백엔드 요청서**로 나누어 진행했다. 2026-10-07에 기능별 로컬 커밋으로 정리했으며 원격 push·배포는 하지 않았다. [커밋별 변경 안내](./commits.md)에서 필요한 작업 단위부터 확인할 수 있다.

## 1. 화면과 동작을 구현한 부분

| 기능           | 달라진 점                                                                                           |
| -------------- | --------------------------------------------------------------------------------------------------- |
| 가견적 입력    | 화장실 개수 추가, 기본 정보·공사 조건 필수 검증                                                     |
| 공정 선택      | 전체 선택/해제, 선택한 공정만 상세 표시, 입력 완료 수 표시, 빠진 항목을 자동으로 열어 안내          |

| 서버 장애·점검 | 점검 화면, 연결 다시 확인, API 장애 시 입력을 유지하는 안내창                                       |
| 종합 인사이트  | 먼저 확인할 항목 3개, 진단 근거로 이동, 업체에 보낼 전체 질문 복사                                  |

개인정보·이용약관은 `/privacy`, `/terms`에 **검토용 초안**을 적용했다. 김승찬 개인 운영(사업자등록 없음), 문의 이메일 muneo777@naver.com을 반영하고 푸터·가입 화면에서 연결했다. [초안 적용 기록](./policy-draft.md)에서 미확정 항목을 확인할 수 있다.

피드백은 **서버 저장 없이 체험하는 단계**다. 실제 서비스에서는 기본으로 숨겨지고, 개발 서버의 `/preview/diagnosis`에서 바로 확인할 수 있다. 점검 화면은 `/maintenance`다.

## 2. 기획까지 정리한 부분

- **로그인·회원가입:** 가입 필드 최소화, 카카오까지 원래 작업 복귀, 비밀번호 재설정, 티켓 만료 안내, 모바일 인증 화면 개선.
- **개인정보·약관:** 수집 항목 조사, 공개 페이지 구성, 동의 방식, 버전/동의 기록 관리, 운영 정보 확정 목록.
- **공통 공사 정보:** 한 번 입력한 집 정보를 가견적과 진단에서 함께 쓰는 구조. 현재 두 API의 필드/값이 달라 통일 작업이 필요하다.
- **공정 분류:** 금액 산출에 쓰는 항목을 우선하고, 브랜드·규격 세분화는 실제 단가 데이터와 함께 확장한다.

## 3. 백엔드에 요청할 부분

**피드백 API는 새로 요청해야 한다.** 바로 전달할 수 있는 [백엔드 요청문](./backend-request.md)을 준비했다.

필수 요청은 피드백 저장·수정·조회·삭제, 저장된 진단 결과 연결, 본인 결과 소유권 검사, 데이터 보유/삭제 정책이다. 서버 복구를 정확히 확인할 공개 헬스 API도 협의안에 포함했다.

## 4. 아직 확정하지 않은 부분

- 개인정보 처리방침과 이용약관의 미확정 운영 정보·최종 문안·시행일·가입 동의 연동·배포.
- 피드백의 실제 서버 저장 및 재조회.
- 공사 정보 공통화.
- ‘공간 상황’ 입력 제거 여부. 현재 `거주중공사`로 전송하므로, 백엔드 산출에 사용하지 않는다고 확인되면 제거한다.

자세한 확인 방법은 [개발·검토 가이드](./README.md), API 필드는 [상세 계약안](./backend-contract.md), 인증/약관은 [기획 문서](./ux-and-policy.md)에 있다.

## 5. 검증 결과

아래는 최초 구현 시 검증 결과다.

- 웹 자동 테스트: 22개 파일, 173개 테스트 통과.
- 웹 타입 검사·린트·프로덕션 빌드, E2E 코드 타입 검사 통과.
- 핵심 브라우저 흐름 4개 확인: 피드백 체험, 장애 안내 후 입력 유지, 로그인 후 원래 화면 복귀, 선택 공정의 필수 입력 검증.
- 모바일·데스크톱 미리보기 및 점검 화면을 시각적으로 확인.

브라우저 검증은 mock API 기준이다. 전체 E2E·시각 회귀 검증을 완료한 것은 아니며, 실제 백엔드의 피드백 저장은 API 개발 후 별도로 확인해야 한다.

후속 요청으로 항목별 실제 문제 여부 기록을 UI·요청 타입·백엔드 요청문에서 제거했다. 이 수정은 기존 피드백 테스트 4개, 웹 타입 검사, 변경 코드 린트로 재검증했다. 운영 정보의 확인 담당자와 자료 위치는 [개인정보·약관 기획](./ux-and-policy.md#운영-정보는-어디서-확인하나)에 추가했다.
