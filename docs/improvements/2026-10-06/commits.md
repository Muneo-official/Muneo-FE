## 변경 내용을 확인하는 명령

저장소 루트에서 전체 순서를 보려면:

```bash
git log --reverse --oneline dd706f0..HEAD
```

예를 들어 진단 피드백의 설명과 변경 파일 목록은 다음 명령으로 확인한다.

```bash
git show --stat 648cb9f2
```

세부 코드까지 보려면 `--stat`을 제외한다. 인증·점검, 인사이트·피드백처럼 같은 파일의 다른 변경은 별도 커밋으로 나눴다. 뒤 커밋이 앞 커밋의 공통 코드에 의존하므로 독립 cherry-pick이나 되돌리기 전에는 인접 커밋도 함께 확인한다.

## 구현 완료와 외부 연동 필요 범위

- **현재 구현**: 입력/인사이트/장애/정책/피드백 화면, 어드민 사용자 이용 내역 UI와 호출 코드, 로컬 QA.
- **백엔드 필요**: 진단 피드백 저장 API, 관리자 사용자별 이력 조회 API 3개. 프론트 커밋이 존재한다고 실제 DB 저장·조회까지 완료된 것은 아니다.
- **운영 확정 필요**: 개인정보 보관 기간·처리 업체·최종 정책 문안·시행일·필요한 동의 이력 수집.
- **현재 미제공**: 원본 업로드 파일 조회, 약관 동의 이력, 가입/최근 접속 일시, 저장하지 않은 생성 결과.

## 검증 기록

기능 구현 단계의 최종 코드에 대해 웹 테스트 173개와 핵심 웹 E2E 4개, 어드민 테스트 46개와 브라우저 시나리오 2개, 두 앱의 타입 검사·빌드를 확인했다. 전체 웹 E2E/시각 회귀와 실제 서버 DB 저장·조회 검증을 완료한 것은 아니다.

커밋 분리 시 각 커밋의 기존 Husky/lint-staged 검사 훅을 실행했다. 부분 변경 복원 중 훅 충돌이 한 번 발생했으나 원본을 보존한 뒤 분리해 재실행했으며, 기능·검증 커밋 14개 작성 후 **154개 변경 파일 전체가 분리 전 최종 파일과 동일함**을 확인했다. 각 중간 커밋을 별도로 빌드한 것은 아니다. 이 안내와 커밋 상태 설명만 문서 커밋에서 추가·수정했다.
