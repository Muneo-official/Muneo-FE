# 어드민 사용자 데이터 확인 가이드

2026-10-10 갱신. 백엔드 확정 명세와 기존 환경 배포 안내를 받아 프론트 연결을 반영했다. [최신 구현·합동 QA](../2026-10-10/backend-integration.md)를 함께 확인한다. 모노레포에 앱이 함께 있어도 웹의 메모리·브라우저 상태가 어드민에 자동 공유되지는 않는다. 서버에 저장된 사용자 ID 기준으로 연결한다.

## 1. 지금 로컬에서 화면 확인 (약 3분)

저장소 루트에서:

```bash
pnpm qa:admin
```

1. `http://127.0.0.1:5174` 접속.
2. 이메일 `admin@example.test`, 비밀번호 `MuneoQa123!`로 로그인. **QA 모드 전용 가상 계정**이다.
3. 사용자 목록에서 **기록 있는 사용자** 클릭 → **사용자 이용 내역**.
4. **예상 견적**: 총 21건, 다음 페이지 이동(3페이지에 1건), 기록 펼치기 → 입력 정보·총 견적·결과 전체 보기.
5. **견적서 진단**: 기록 펼치기 → 업체·입력 정보·확인할 항목·욕실 공사 상세 확인.
6. **진단 피드백**: good/bad, 선택 이유, 의견, 진단 ID, 생성·수정일 확인. 항목별 실제 문제 여부는 수집·표시하지 않는다.

| 사용자 ID | 확인할 화면                                            |
| --------- | ------------------------------------------------------ |
| 101       | 정상 기록, 견적 21건 페이지 이동, 진단 1건, 피드백 2건 |
| 102       | 정상 응답 + 실제 0건 안내                              |
| 103       | 조회 API 미연결/대상 없음(404), 다시 시도              |
| 104       | 서버 연결 실패(503), 다시 시도                         |
| 105       | 응답 소유자 불일치 → 데이터 표시 차단                  |
| 106       | 관리자 조회 권한 없음(403)                             |
| 107       | 조회 직전 삭제된 사용자(`404 USER_NOT_FOUND`)          |

101에서 펼친 기록이 102 등 다른 사용자 상세에 남아 있지 않아야 한다. 탭 전환 시 첫 페이지로 돌아간다. 로그아웃 후 상세 URL로 접근하면 로그인으로 이동해야 한다.

QA 모드는 모든 `/api/` 요청을 로컬에서 처리하며 실제 서버로 넘기지 않는다. 계정 수정·탈퇴·권한 변경은 405로 막는다. 가상 데이터는 파일에 고정되어 있으며 웹에서 저장한 결과는 이 화면에 나타나지 않는다. `Ctrl+C`로 종료한다. `vite build --mode qa`는 배포 혼동을 막기 위해 실패하도록 했다.

## 2. 실제 서버 데이터 확인

필요한 준비: **같은 백엔드 환경에 연결된 웹·어드민 + 테스트용 USER/ADMIN 계정**. API 명세는 전달받았으며 실제 데이터 검증은 아래 순서로 진행한다. 비밀번호는 문서나 채팅에 남기지 않고 운영자가 직접 입력한다.

1. `apps/admin/.env.local`의 `VITE_API_BASE_URL`과 웹이 사용하는 백엔드 환경이 같은지 확인한다. 미설정 개발 기본값은 `https://api-dev.muneo.kr`다.
2. `pnpm dev:admin` 실행 → 터미널에 표시된 주소(기본 `http://localhost:5173`)에 ADMIN 계정으로 로그인.
3. **별도 브라우저 프로필**의 웹에서 테스트 USER 계정으로 예상 견적 1개와 진단 1개를 생성하고 각각 **저장**한다. 저장하지 않은 결과는 대상이 아니다.
4. 어드민 사용자 목록에서 테스트 계정 이메일 검색 → 사용자 상세 → 이용 내역 새로고침. ID·입력·결과를 웹의 내역 화면과 비교한다.
5. 피드백은 기본 API 모드다. 기존 환경에 `preview`/`disabled` 설정이 있다면 제거하거나 `api`로 변경하고 재시작한다. 저장된 진단에 평가 제출 → 웹 새로고침으로 복원 확인 → 어드민 피드백 새로고침 → 같은 사용자·진단 ID·평가·이유·의견 확인. 수정 시 같은 피드백의 `updated_at`이 바뀌어야 한다. 의견 삭제 후에는 피드백만 사라지고 진단은 남아 있어야 한다.
6. 다른 테스트 사용자로 확인해서 기록이 섞이지 않는지 검사한다. 일반 USER로 관리자 API를 호출하면 서버가 403을 반환해야 한다.

웹과 어드민을 서로 다른 localhost 포트에서 열어도 쿠키는 포트별로 분리되지 않는다. 브라우저 프로필을 분리해 관리자와 사용자 로그인이 서로 덮이지 않게 한다. 관리자 화면은 `/api/v1/users/me`로 서버 권한·계정 일치를 확인한다. 오래된 로컬 로그인 상태만으로는 진입할 수 없다.

## 3. 안 보일 때

| 증상                               | 확인/조치                                                                                                                                                                                      |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| QA 실행 시 포트 사용 중            | 기존 QA 서버를 사용하거나 소유한 프로세스 종료 후 재실행. 임의의 다른 작업 서버는 종료하지 않는다.                                                                                             |
| 로그인 후 다시 로그인 화면         | 개발자 도구 Network에서 login/`users/me` 응답과 쿠키 저장 여부 확인. `ADMIN` 권한·도메인·HTTPS·쿠키 정책을 백엔드와 점검. Dev 프록시는 Domain만 로컬 호스트로 맞추며 Secure를 제거하지 않는다. |
| “조회 API가 아직 제공되지 않거나…” | 관리자 API 미구현(404/501), 잘못된 URL, 대상 사용자 부재를 확인. 0건으로 해석하지 않는다.                                                                                                      |
| 403                                | 로그인 계정의 서버 ADMIN 권한과 해당 경로의 보안 설정 확인. 프론트에서 역할을 바꿔 우회하지 않는다.                                                                                            |
| 503/연결 실패                      | 백엔드·AI 서비스·DB 상태 및 API 프록시 대상 확인. 복구 후 다시 시도.                                                                                                                           |
| 응답 형식/소유자/페이지 오류       | 요청서의 필드·UTC offset 포함 날짜·user_id·페이지 메타데이터와 응답 비교. 개발자 도구의 개인정보는 외부 공유 전에 가린다.                                                                      |
| 정상 응답인데 0건                  | 같은 개발/운영 환경인지, 정확한 사용자 ID인지, 웹에서 실제 저장했는지 확인.                                                                                                                    |

## 아직 조회할 수 없는 범위

- 원본 업로드 파일/파일 다운로드: 현재 저장 이력 응답에는 파일 메타데이터·다운로드 API가 없다.
- 개인정보·약관 동의: 현재 가입에서 동의 버전·시간을 수집하지 않는다. 페이지 링크 열람을 동의로 표시하지 않는다.
- 가입일·최근 접속일·접속 로그: 현재 관리자 계정 응답에 없다. 별도 수집/조회 계약이 필요하다.
- 저장하지 않은 생성 결과, 삭제된 이력 복구: 서버에 보존 여부부터 확인해야 한다.
- 비밀번호·토큰·인증키는 관리자 사용자 데이터 조회 대상에 포함하지 않는다.

실제 서버 배포, ADMIN 권한 부여, 데이터베이스 조회 권한 설정은 이번 프론트 저장소 작업에서 수행하지 않았다. 이 문서와 요청서를 백엔드 담당자에게 전달한 뒤 위 2번 순서로 확인하면 된다.

## 자동 QA와 검증 범위

```bash
pnpm --filter admin test
PLAYWRIGHT_CHANNEL=chrome pnpm test:e2e:admin
```

두 번째 명령은 로컬 Chrome을 사용하며 QA 서버가 없으면 자동으로 기동한다. Playwright Chromium이 설치되어 있으면 `PLAYWRIGHT_CHANNEL=chrome` 없이 실행해도 된다. 기존 웹 E2E 서버(3000/4000 포트)와 별도로 5174를 사용한다.

2026-10-07 확인: 어드민 테스트 46개, 브라우저 시나리오 2개, 프로덕션 빌드 통과. 브라우저에서 로그인·견적 페이지 이동·진단 항목·피드백 상세·서버 로그아웃과 모바일 오류/빈 상태를 확인했다. 이 검증의 데이터는 로컬 QA fixture이며 실제 DB 저장/조회 성공을 의미하지 않는다. 린트에는 기존 `ToastProvider.tsx`의 Fast Refresh 경고 1개가 남아 있다.

2026-10-07에는 개발 서버 공개 명세 조회를 실행하지 못했으나, 2026-10-10에는 직접 조회(HTTP 200)해 관리자 로그인 및 이용 내역 3개 경로가 배포 명세에 등록되어 있음을 확인했다. [관리자 로그인 확인 기록](../2026-10-10/backend-integration.md#관리자-로그인에서-막힐-때)을 참고한다. 실제 ADMIN 계정으로 로그인한 뒤 DB 기록이 보이는지는 별도로 검증해야 한다.
