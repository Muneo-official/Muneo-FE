# 백엔드 전달용 요청문

견적서 진단 결과에 대한 사용자 피드백 기능을 추가하려고 합니다. 프론트 UI는 미리보기로 구현해 두었고, 저장 API 신규 개발을 요청드립니다.

## 필요한 API

| 기능      | 제안 경로                                           | 동작                                       |
| --------- | --------------------------------------------------- | ------------------------------------------ |
| 저장·수정 | `PUT /api/v1/risk-detector/{report_id}/feedback`    | 본인 진단 결과의 피드백 1개 생성 또는 갱신 |
| 조회      | `GET /api/v1/risk-detector/{report_id}/feedback`    | 이력 재방문 때 기존 피드백 복원            |
| 삭제      | `DELETE /api/v1/risk-detector/{report_id}/feedback` | 사용자 의견 철회                           |

## 저장할 값

- 전체 평가: `good` / `bad` (필수)
- 선택 이유: 복수 enum (선택)
- 추가 의견: 최대 500자 (선택)
- 연결 정보: 진단 결과 ID, 로그인 사용자, 결과 버전, 생성·수정 시각

피드백은 저장된 진단 결과 전체에 연결합니다. 항목별 실제 문제 여부는 수집하지 않으므로, 개별 공정/항목의 고정 ID 추가는 이번 요청에 포함하지 않습니다.

## 함께 확인 부탁드릴 사항

1. 현재 분석 응답에는 저장 전 결과 ID가 없어, 우선 결과를 저장한 후 피드백을 보내는 방식으로 구현했습니다. 이 방식으로 진행 가능한지 확인 부탁드립니다.
2. 동일 사용자·결과에 PUT을 여러 번 보내도 피드백 한 건만 유지되도록 부탁드립니다.
3. 로그인 세션에서 사용자와 결과 소유권을 검증하고, 다른 사용자의 결과에 제출할 수 없도록 부탁드립니다.
4. 결과/회원 삭제 시 피드백 삭제, 의견 보유 기간과 관리자 열람 범위도 합의가 필요합니다.

요청·응답 예시, enum, 오류 상태와 검증 조건은 [상세 계약안](./backend-contract.md)에 정리했습니다. 경로와 응답 형식은 기존 백엔드 규칙에 맞춰 조율 가능합니다.
