## 바로 확인하기

기존 API 환경변수가 설정된 개발 환경에서:

```bash
pnpm dev:web
```

- `http://localhost:3000/preview/diagnosis`: 로그인/API 없이 인사이트, 질문 복사, good/bad, 이유, 의견 입력을 확인한다. 예시 데이터만 사용하며 서버에 저장하지 않는다.
- `http://localhost:3000/maintenance`: 연결 장애 화면을 확인한다. ‘연결 다시 확인’은 실제 서버의 도달 여부를 검사한다.
- `/privacy`, `/terms`: 로그인 없이 개인정보·이용약관 초안, 운영자·문의 이메일, 확인이 필요한 항목을 확인한다. 가입 화면에서는 새 탭으로 열린다.
- 로그인 후 `/home`: 두 가지 시작 카드와 최근 이력을 확인한다.
- `/estimate`: 모든 기본값과 화장실 개수 입력 → 전체/부분 공정 선택 → 미완료 상태로 다음 버튼 → 해당 상세 설정으로 이동하는지 확인한다. 욕실 도기는 ‘교체 안함’을 명시적으로 선택할 수 있다.
- 실제 진단 완료 화면과 `/history/[id]`에도 같은 종합 인사이트를 사용한다. 결과를 저장해도 화면을 유지하여 이어서 검토할 수 있다.

기존 3000번 서버를 유지한 채 다른 포트를 쓰려면:

```bash
E2E_DIST_DIR=.next-review pnpm --filter web exec next dev --port 3100
```

주소의 포트만 3100으로 바꾼다. 모든 `NEXT_PUBLIC_*` 값은 번들 생성 시 반영되므로 변경 후 개발 서버 재시작/프로덕션 재빌드가 필요하다.

### 실제 결과 화면에서 피드백 UI 보기

10월 10일부터 기본 API 모드다. 모드를 명시하려면 `apps/web/.env.local`에 다음을 추가하고 개발 서버를 재시작한다.

```dotenv
NEXT_PUBLIC_DIAGNOSIS_FEEDBACK_MODE=api
```

| 값                | 동작                                                       |
| ----------------- | ---------------------------------------------------------- |
| 미설정 또는 `api` | 저장된 진단의 실제 피드백 조회·저장·수정·삭제. 현재 기본값 |
| `disabled`        | 피드백 UI 숨김                                             |
| `preview`         | 실제 결과 아래에 체험 UI 표시. 의견 저장/서버 전송 없음    |

`/preview/diagnosis`는 개발 중 공개되며, 프로덕션에서는 기본적으로 404다. 리뷰 배포에서만 `ENABLE_UI_PREVIEWS=true`로 열 수 있다. 이 변수는 실제 데이터 접근을 허용하는 기능이 아니다.

### 점검 운영

```dotenv
MAINTENANCE_MODE=true
MAINTENANCE_MESSAGE=안정적인 서비스 제공을 위해 점검 중이에요. 잠시 후 다시 방문해 주세요.
```

- 서버 환경변수로 관리한다. 반영에 서버 재시작/재배포가 필요한 환경인지 배포 방식에 맞춰 확인한다.
- 보호된 화면은 점검 페이지로 이동하고, 프록시 API는 `503`과 `Retry-After: 60`, `Cache-Control: no-store`를 응답한다. 랜딩은 서비스 소개를 위해 유지한다.
- 실제 API가 502/503/504를 반환하면 입력을 유지한 안내창을 띄운다. 닫거나 연결 확인에 성공해도 제출 요청을 자동 재실행하지 않는다. 사용자가 직접 재시도한다.
- 서버 렌더링/인증 갱신 도중 백엔드 연결 실패도 점검 화면으로 보낸다. 정상적인 인증 거절은 로그인 흐름을 따른다.
- `/api/service-status`는 공개 헬스 API가 없어, 쿠키를 보내지 않은 `/api/v1/users/me`의 2xx/401로 서버 도달 여부만 판단한다. 진단 엔진 전체 복구를 보장하지 않는다. 전용 readiness API로 교체할 위치다.
- 브라우저 자체 오프라인/일반 500은 개별 작업 오류로 안내한다. 모든 오류를 계획 점검이라고 단정하지 않는다.
- 이 UI는 Next.js가 살아 있을 때 백엔드 중단을 안내한다. 프론트 호스팅 자체 중단은 앱 코드가 실행되지 않으므로 CDN/호스팅의 정적 오류 페이지가 별도로 필요하다.

## 공정 분류 개선안

선택지를 무조건 늘리기보다 실제 산출에 쓰는 값을 수집한다. 이번에 API에 전달되지 않던 철거 범위 상세 선택을 제거했으며, 철거 여부는 공정 선택으로 계속 전달한다.

| 공정      | 이번 입력                                      | 세분화 조건                                                                           |
| --------- | ---------------------------------------------- | ------------------------------------------------------------------------------------- |
| 도배      | 실크/합지/천연, 전체/벽면/부분 공간, 초배 여부 | 브랜드·제품·폭·벽 상태에 대응하는 단가 데이터와 API 필드가 확보될 때 확장             |
| 바닥      | 자재 종류, 범위, 기존 바닥 철거 여부           | 두께·시공 패턴별 사례 수 및 단가 보정 검증 후 추가                                    |
| 욕실      | 기본 정보의 개수, 크기, 타일 등급, 도기 교체   | 부분 시공/욕실별 서로 다른 크기는 별도 모델로 확장                                    |
| 주방      | API가 지원하는 싱크 형태                       | 현재 `ㄱ자(일자)`처럼 혼재된 용어는 엔진 enum과 함께 일자/ㄱ자/ㄷ자/아일랜드로 재정의 |
| 기타 공정 | 포함 여부                                      | 세부 입력이 금액에 반영되는 API부터 순차 확장                                         |

‘모름’은 현재 백엔드가 받는 초배·바닥 철거·트럭 접근에서만 제공한다. 근거 없는 기본값을 정답처럼 미리 선택하지 않는다. 브랜드/모델은 선택 목록을 길게 늘리기보다 제품명 선택 검색 또는 선택적 자유 입력이 적합하며, 단가 검색 규격을 먼저 정한다.

### 공사 정보 공통화 2차안

홈에서 ‘우리 집 정보’ 1회 입력 → 견적 생성과 진단이 같은 정보로 시작하는 방식이 목표다. 이번에는 별도 계정 정보 스토어를 만들지 않았다. 현재 방 개수는 견적에서 `4개 이상` 범주형, 진단에서 정확한 숫자이고 건물 연식 enum도 달라 그대로 공유하면 데이터가 손실된다.

공통 `ConstructionProject`에 지역·공간 유형·전용 면적·정확한 방/욕실 수·건물 연식·층수·엘리베이터를 둔다. 견적 전용 공정/자재와 진단 전용 업체명/첨부파일은 각 플로우에 남긴다. 새 작업을 시작할 때 최근 공사 정보 불러오기/새로 입력 선택, 기존 저장 결과는 당시 입력 스냅샷 유지, 프로젝트 변경 시 생성 결과 무효화를 함께 구현한다. 계정별 저장 API와 두 엔진의 공통 필드 계약이 먼저 필요하다.

## 종합 인사이트 판단 기준

기존 `buildInsights`는 건수만으로 같은 세 문장을 반복했다. 지금은 실제 진단 항목에서 누락→불분명→중복 순으로 최대 3개를 요약한다. 이는 작업 순서 제안이며 금액·발생 확률을 계산한 위험 점수가 아니다. 전체 질문 복사에는 화면에서 요약하지 않은 항목도 포함한다. 서버가 제공한 상태값을 제목의 단어만 보고 다른 상태로 바꾸던 추론을 제거하여 원래 분류를 보존한다.

다음 개선은 원문 견적서의 페이지/행 위치와 증거 문구 표시다. 이를 위해서는 OCR 좌표와 근거 응답 확장이 필요하다. 이번 피드백은 전체 평가·이유·의견만 수집하며 항목별 실제 문제 여부나 해결 여부 기록은 제외한다.

## 검증 범위

입력 검증, 화장실 개수 매핑, 401 갱신/동시 갱신 병합/POST 본문 유지, 503 알림, 피드백 미리보기·실패·재시도, 이메일 복귀 주소를 자동 검증한다. E2E는 별도 mock 서버로 사용자 흐름을 확인하며 실제 진단 엔진의 금액 정확도나 피드백 서버 저장을 검증한 것은 아니다. Linux 시각 회귀 기준 이미지는 다시 생성하지 않는다.

Vercel CLI로 배포할 때는 호환성을 위해 `npm i -g vercel@latest`로 최신 버전 업데이트를 권장한다. 이번 작업에서 CLI 업데이트나 배포는 실행하지 않았다.
